# Adora Agent — Brain V1 (read-only preview)

هذه نسخة تطويرية غير مفعلة من محرك Adora Agent. **لا ترسل أي رسالة، ولا تنشئ أو تعدّل طلبات ERP، ولا تغيّر حالة المحادثات.**

## الوضع الحالي
- دالة Supabase Edge Function باسم `adora-agent`، مدعومة بنموذج `gpt-6-luna` المحدد للمشروع (يجب التأكد من توافره لحساب API قبل الاعتماد عليه).
- تقرأ `luna_messages` (آخر 30 يومًا، عينة حتى 40 رسالة) و`luna_conversation_state`.
- تقرأ أكواد المنتجات من `agent_product_codes` وأسعار المقاسات ومخزونها من `products` و`product_variants` بعد ضبط `ADORA_STORE_ID`.
- تُرجع مسودة قرار منظمة، ولا ترسلها إلى Meta.
- تدعم حالياً Messenger فقط. Instagram غير مفعل في هذه النسخة.
- لا تعالج الصور/الفيديو فعليًا؛ توجهها للمراجعة البشرية.
- **لم يتم ربط الوظيفة بـ `meta-webhook` بعد**؛ رفع الملف إلى GitHub ليس نشرًا في Supabase.

## الأسرار والمتغيرات
- `OPENAI_API_KEY`: غير موجود بحسب لقطة Supabase الأخيرة؛ أضفه في Edge Functions Secrets، ولا تضع قيمته هنا أو في GitHub.
- `ADORA_STORE_ID`: معرّف متجر/مخزن Adora في ERP. لا تستنتجه من اسم فقط؛ استخرجه من قاعدة البيانات قبل تفعيل استعلامات الكتالوج.
- `SUPABASE_URL`: متغير Supabase تلقائي.
- المصادقة على الاستدعاء عبر `service_role` وRPC `luna_storage_health` التي تستخدمها وظيفة Luna الموجودة.
- إعداد `Verify JWT` يحتاج مراجعة متسقة مع التحقق الداخلي عند النشر.

## قبل الاختبار الإنتاجي
1. تأكد من بنية الأعمدة وقيود `luna_messages` و`luna_conversation_state` الفعلية.
2. راجع اسم ومعرّف نموذج OpenAI وإتاحة Structured Outputs له باستخدام حساب API.
3. راجع قواعد الصلاحيات والتحويل للموظف، وخذ موافقة صريحة قبل إرسال رسائل أو تغيير طلبات.
4. اختبر على بيانات غير إنتاجية ثم انشر Edge Function يدويًا أو عبر مسار CI مصادق عليه.
5. لا تربط Webhook تلقائيًا قبل تصميم سجل معالجة وعدم تكرار؛ لا نستخدم Queue منفصلًا.

## الأمان
هذه الوظيفة مُصممة للقراءة فقط. لا تخزن المفتاح في GitHub، لا تفعّل الرد التلقائي، ولا تجعل التنبؤات من نموذج AI تكتب بيانات ERP مباشرة.
